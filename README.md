# PostgreSQL MD5 보안 실습 랩 & 공격 시연 보고서

본 랩 환경은 구형 DB 접근 제어 솔루션의 제약으로 인해 PostgreSQL 인증 방식을 `scram-sha-256`에서 `md5`로 다운그레이드할 것을 요구받았을 때 발생하는 **암호학적 오해와 실질적인 보안 위협**을 검증하고 실습하기 위해 구축되었습니다.

---

## 1. 암호학적 핵심 쟁점: "MD5 충돌 공격으로 DB 인증이 뚫릴까?"

> **결론부터 말하면: "아닙니다. 충돌 공격(Collision Attack)으로는 DB 로그인을 뚫을 수 없습니다. 하지만 MD5는 다른 치명적인 취약점(Pass-the-Hash, 초고속 크래킹)으로 인해 완벽히 뚫립니다."**

### 1) 충돌 공격(Collision) vs 역상 공격(Pre-image)의 차이
* **충돌 공격 (Collision Attack - MD5 취약)**:
  공격자가 임의의 두 입력값 $M_1 \ne M_2$를 직접 생성하여 $\text{MD5}(M_1) = \text{MD5}(M_2)$가 되게 만드는 공격입니다.
  이는 **전자 서명 위조, 계약서/인증서 변조, 파일 무결성 우회** 등에 치명적입니다.
* **역상 공격 (Pre-image Attack - MD5 여전히 불가능, 복잡도 $2^{128}$)**:
  서버에 이미 등록된 특정 해시값 $H_{target}$이 주어졌을 때, $\text{MD5}(M) = H_{target}$을 만족하는 원래 비밀번호 $M$을 수학적으로 역산해내는 공격입니다.
  **패스워드 인증 시스템을 뚫기 위해서는 충돌 공격이 아니라 '역상 공격'이 필요합니다.**

### 2) PostgreSQL의 챌린지-응답 구조
PostgreSQL에 접속할 때 서버는 매 세션마다 4바이트의 암호학적 난수 **Salt**를 클라이언트에 전송합니다.
클라이언트는 최종적으로 `md5(md5(password + username) + salt)`를 반환해야 하므로, 공격자가 사전에 미리 계산해 둔 해시 충돌 쌍을 사용하는 것은 원천적으로 차단됩니다.

따라서 **"MD5 충돌 공격으로 DB 로그인을 한 방에 뚫어버린다"는 것은 암호학적 공격 유형을 혼동한 대표적인 오해**입니다.

## 2. 그렇다면 MD5는 안전한가? (실제 치명적 위협)

비록 충돌 공격 때문은 아니지만, PostgreSQL에서 MD5 인증을 켜는 순간 **보안상 심각한 구멍**이 발생합니다:

1. **Pass-the-Hash (해시 전달 공격)**:
   * PostgreSQL MD5 인증의 가장 큰 설계 결함입니다.
   * 클라이언트가 인증 토큰을 생성할 때 **평문 비밀번호를 전혀 몰라도** `pg_authid`에 저장된 해시값만 있으면 완벽한 인증 응답을 만들어 낼 수 있습니다.
   * 즉, SQL Injection, DB 백업 파일 유출 등으로 해시만 얻어내면 **비밀번호를 풀 필요도 없이 해시 그대로 로그인**이 가능합니다. (`SCRAM-SHA-256`은 암호학적으로 이를 원천 차단함)
2. **초고속 오프라인 사전 공격 (Dictionary / Brute-force Attack)**:
   * `SCRAM-SHA-256`은 **4,096번의 PBKDF2 반복 연산(Key Stretching)**을 강제합니다.
   * 반면 MD5는 반복 연산이 1회에 불과하여 연산 비용이 사실상 0에 수렴합니다. GPU 1대로도 초당 수백억 번의 무차별 대입이 가능하여 일반적인 비밀번호는 수 초 안에 전부 노출됩니다.
3. **네트워크 스니핑 후 패킷 크래킹**:
   * 네트워크 구간에서 와이어샤크나 미러링 포트로 패킷을 캡처하면 `Salt`와 `Client Response`가 노출되며, Hashcat (Mode 11100)을 통해 초고속으로 평문 패스워드가 탈취됩니다.

## 3. 환경 구성 및 실행 방법

### 구성 파일 안내
* `docker-compose.yml`: `postgres:latest` 이미지를 기반으로 MD5 인증이 활성화된 PostgreSQL 컨테이너 구동 설정
* `config/postgresql.conf`: `password_encryption = md5` 적용
* `config/pg_hba.conf`: 인증 방식을 `md5`로 강제 적용
* `init-scripts/01-init-dummy-data.sql`: 기업 기밀 데이터 및 MD5 암호화 계정(`app_user`, `auditor`) 생성

### 1) 컨테이너 기동 및 데이터 확인
```bash
# 컨테이너 실행
docker compose up -d

# 실행 상태 및 로그 확인
docker compose ps
docker logs postgres_md5_lab
```

## 5. 보안팀 대응 및 아키텍처 권고사항

1. **PostgreSQL 공식 권고사항**:
   PostgreSQL 14부터 기본 인증이 `scram-sha-256`으로 전환되었으며, PostgreSQL 18+ 로그에서도 볼 수 있듯이 **MD5 지원은 공식적으로 Deprecated 되었으며 차기 버전에서 완전 제거될 예정**입니다.
2. **구형 접근 제어 솔루션 대응 방안**:
   * **원칙**: 보안을 위해 도입한 'DB 접근 제어 솔루션' 때문에 정작 DB 자체의 암호화 체계를 20년 전 취약 알고리즘(MD5)으로 다운그레이드하는 것은 주객전도이자 감사(ISMS-P, 금융보안원 규정 등) 지적 사항입니다.
   * **해결책**:
     1. 해당 솔루션 벤더에 `SCRAM-SHA-256` 지원 패치(libpq 10+ 드라이버 연동) 요청.
     2. 네트워크 프록시 방식 대신 eBPF / 호스트 기반 로깅 에이전트로 접근 기록 수집 체계 전환.
     3. 부득이하게 과도기적으로 MD5를 써야 할 경우, DB 포트(5432)를 접근 제어 솔루션의 고정 IP에서만 접속할 수 있도록 방화벽/보안그룹을 극도로 제한하고 외부 직접 접근을 엄격히 차단해야 합니다.
